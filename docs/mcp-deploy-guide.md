# MCP и База Знаний: деплой и первая проверка на платформе

Актуально на 2026-08-28. Общие правила Git-деплоя и восстановления файлов —
`docs/deploy.md`; здесь описана только проверка чтения Базы Знаний.

## Что уезжает на платформу

Платформа принимает следующие ресурсы проекта:

- `functions/ID_Tools/getKnowledgeMcp/` — чтение размеченных статей нашего пространства;
- `functions/ID_Tools/findOperatorKnowledge/` — поиск по всей доступной БЗ только для
  внутренней подсказки оператору;
- `nodes/functions/func_find_operator_knowledge.yml` — кодовый шаг перед обычным handover;
- `nodes/conditions/cond_routing_subtask.yml` — отрицательная ветка маршрутизации ведёт в
  этот шаг;
- `credentials/custom/1000299722-kbmcptoken-vod.yml` — только метаданные credential;
- существующая MCP-интеграция и её credential в `integrations/mcp/` и `credentials/mcp/`.

Секретного значения в YAML нет. Токен хранится в UI Agent Platform. `origin-key` вручную
не менять: при импорте и экспорте его обслуживает платформа.

`getKnowledgeMcp` и `findOperatorKnowledge` обращаются к MCP прямым JSON-RPC через `Http`.
Неймспейса `MCP.call` в user functions платформы нет. MCP-интеграция остаётся в проекте,
но эти две функции не вызывают её узел: только так можно передать фильтр `request.spaces`
и детерминированно управлять fallback.

## До деплоя

1. Рабочее дерево должно быть чистым: все нужные изменения просмотрены и закоммичены.
2. В репозитории не должно быть токенов. Локальный токен допустим только в игнорируемом
   `.env.local` как `MCP_KB_TOKEN`.
3. Выполнить:

   ```bash
   node tools/build-knowledge.js --check
   node tests/run.js
   node tests/dialog.check.js
   ```

4. Деплоить только штатным скриптом:

   ```powershell
   pwsh tools/deploy.ps1
   ```

Скрипт сам получает экспорт платформы, восстанавливает `docs/`, `tests/`, `tools/`,
проверяет потери, повторно запускает тесты и только после этого пушит `main`.

## После импорта

1. В UI открыть Credentials → `kb-mcp-token`.
2. Вставить действующий read-only токен БЗ и сохранить.
3. Дождаться обратного экспорта платформы.
4. Выполнить `git fetch origin` и сначала только посмотреть:

   ```bash
   git log --oneline HEAD..origin/main
   git diff --name-status HEAD..origin/main
   ```

Нужно убедиться, что платформа сохранила новую функцию, её схему, узел и связь графа.
Удаление `docs/`, `tests/`, `tools/` в экспорте ожидаемо; на следующем запуске
`tools/deploy.ps1` они будут восстановлены при слиянии.

## Первый smoke-тест

### Неизвестная тема

В тестовом чате отправить реальное обращение, для которого нет утверждённой статьи нашего
пространства, но по которому ожидаются материалы в общей БЗ.

Ожидание:

- обращение всё равно передаётся оператору;
- партнёр получает только стандартную отбивку о передаче;
- во внутренней переписке есть до трёх возможных материалов: заголовок, пространство,
  excerpt и ссылка;
- результаты поиска не появляются в сообщении партнёру;
- ошибка MCP или отсутствие результатов не блокируют handover.

### Контрольная известная тема

Отправить, например: `Тамбов-1, на кассе ресторана ККМ не подключен`.

Ожидание: выбирается `pos_terminal_troubleshooting`, бот выдаёт утверждённый совет, а
общий операторский поиск не вызывается.

### Контрольная отрицательная тема

Отправить: `Тамбов-1, нужно поменять аватарку у курьера`.

Ожидание: статья о выводе чаевых не выбирается; обращение передаётся оператору и только
оператор может получить подсказки общего поиска.

## Что смотреть в логах

- `findOperatorKnowledge: … → N подсказок оператору` — поиск и шаблон ссылок сработали;
- `credential … не читается` — проверить заполнение `kb-mcp-token`;
- HTTP 401 — токен недействителен или отозван;
- HTTP 406 — запрос не объявил одновременно JSON и `text/event-stream`;
- ошибка JSON-RPC или разбора SSE — сохранить форму ответа из лога перед изменением кода.

добавлять ни в документацию, ни в тестовые примеры, ни в commit message.
