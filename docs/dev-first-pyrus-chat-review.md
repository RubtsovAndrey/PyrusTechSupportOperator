## Границы приёмки

Вход не уточняет, кому принадлежит аватарка. Черновик предполагает карточку сотрудника;
шаги подтверждены статьёй, но применимость статьи к намерению партнёра не установлена.
Для такого вопроса оператору следует уточнить объект или сделать ответ условным.
Это ограничение качества подсказки остаётся открытым; утверждать, что все части
черновика однозначно отвечают исходному намерению, нельзя.

Техническая цепочка dev → поиск → Selector → Composer → внутренняя сводка подтверждена
для одного витка. Не проверены сохранение вопроса после уточнений, неоднозначный юнит,
рейтинговая подзадача и кассовые сценарии именно в dev. По одной выгрузке dev нельзя
доказать отсутствие параллельного обращения в main; факт доставки в dev подтверждён.

Изменения кода не потребовались. Следующий тест — новый чат с явным вопросом о курьере,
поздним юнитом и уточнением бизнеса по [подготовленной инструкции](dev-avatar-smoke.md).
Результат оценивать по реальным прочитанным статьям и окончательной сводке.
