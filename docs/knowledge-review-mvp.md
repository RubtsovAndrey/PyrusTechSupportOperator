# Проверка знаний для MVP

Статус: решения подтверждены владельцем продукта 3 сентября 2026 года.

Дата: 3 сентября 2026 года.

## Текущее пространство

После резервного копирования опубликованы только четыре кассовые статьи. Шесть тестовых
статей переведены в черновики и не попадают в поиск опубликованных материалов. Новые
рейтинговые материалы пока не публиковались.

Статусы Agent Platform отдельно не менялись: уже загруженный туда каталог будет приведён в
соответствие с БЗ на этапе реализации и деплоя.

## Кассовые сценарии

| Сценарий | Предлагаемый режим MVP | Основание и граница |
|---|---|---|
| Смена больше 24 часов | Ответ партнёру | Уже утверждён; выполнять только для кассовой смены и доступного Тест драйвера ККТ |
| Ошибка 148 / превышение длины реквизита | Ответ партнёру | Общая БЗ связывает превышение длины реквизита с ИНН кассира; августовские ответы операторов повторяют тот же обходной путь |
| Смена закрыта, Z-отчёт не вышел | Ответ партнёру | Печатать копию можно только если смена закрыта и после неё не печатались другие фискальные документы |
| Другие ошибки кассы, ККМ и терминала | Только подсказка оператору | Текущая статья объединяет разные причины и компоненты; ветки ещё не утверждены отдельно |

Эвристический подсчёт по первым сообщениям 930 кассовых чатов нашёл 25 явных упоминаний
смены больше 24 часов, 8 явных случаев ошибки 148 и 107 упоминаний Z-отчёта. Только четыре
первых сообщения одновременно явно говорили, что смена закрыта и отчёт не вышел: это
подтверждает необходимость уточнений, а не массового применения инструкции по слову
«Z-отчёт». Входящих формулировок JavaScript и `ERR_NAME_NOT_RESOLVED` в этой выборке не
обнаружено, явных проблем соединения с ККМ — около семи.

Подсчёт служит оценкой покрытия, а не бизнес-истиной: он основан на текстовых признаках и
не заменяет ручную приёмку.

### Исправления общих правил касс

- Российский сценарий можно начать под рабочим предположением РФ, даже если юнит ещё не
  определён. Подтверждённый юнит обязателен для закрытия, но не для первого безопасного
  совета.
- В сценарии ошибки 148 нельзя просить фотографию: любое вложение переводит чат оператору.
  Достаточно полного текста ошибки.
- После неуспеха не выдаётся следующий совет из соседней кассовой ветки.
- Для широкой кассовой темы компонент выбирается по фактической проблеме: JavaScript и
  белый экран относятся к приложению кассы, проблемы соединения с ККМ — к печати чека,
  банковский терминал — к оплате картой. Общий компонент «Печать чека» для всех веток
  неверен.

## Рейтинги

В выборке 48 чатов РКО и 35 чатов Рейтинга стандартов. В них встречаются апелляции,
критерии, баллы, статусы, вопросы о проверках, предупреждения о ремонте или закрытии, а
также пустые и ошибочно размеченные обращения. Поэтому исторический компонент нельзя
использовать как входной признак: тему нужно определять из разговора.

Предлагается один маршрут `ratings` с двумя вариантами компонента. Для партнёрского ответа
на первом этапе разрешаются только четыре полностью прочитанные статьи из пространства
«Стандарты управления и внедрения в Евразии»:

| Вид | Статья | ID | Проверенная версия |
|---|---|---|---|
| РКО | Рейтинг клиентского опыта: принципы и правила | `272d65f9-ca3b-4d54-a1ce-5a9fff4a04eb` | 22.05.2026 |
| РКО | Правила подачи апелляций по рейтингу клиентского опыта | `8e0617e4-bead-4be1-8796-12b18b214dc5` | 23.09.2025 |
| Рейтинг стандартов | Рейтинг стандартов: принципы и правила | `4c1ae39a-6d5e-4235-809e-98d73ad95111` | 31.07.2026 |
| Рейтинг стандартов | Рейтинг стандартов: правила подачи апелляций | `467785e9-2a21-4bb5-877b-857dbffafea7` | 18.07.2025 |

Поиск по всему актуальному пространству остаётся первым шагом, но партнёрский ответ
разрешён только для совпавшего ID из списка. Это защищает от статей Казахстана, Турции,
архивов и MD Audit, которые реально появляются в общей выдаче по запросу об апелляции.

## Подтверждённые решения

1. Разрешён партнёрский ответ по ошибке 148 в формулировке: выбрать другого кассира для
   текущего чека; управляющему проверить и исправить ИНН в карточке сотрудника. При
   сохранении ошибки — оператор.
2. Разрешён партнёрский ответ для закрытой смены без Z-отчёта только после подтверждения,
   что смена закрыта, после неё не печатались другие документы и Тест драйвера ККТ доступен.
3. Остальные ветки широкой статьи «Касса, ККМ и терминал» остаются операторскими до
   отдельного разбора и исправить назначаемые им компоненты по типу проблемы.
4. Четыре рейтинговых источника утверждены как начальный allowlist; утверждено предупреждение:
   «Материал подобран автоматически и может не учитывать особенности вашей ситуации».

Рейтинговый маршрут приведён к исполняемой схеме и опубликован в нашем пространстве как
`[RATINGS] Обработка вопросов по рейтингам`. Четыре источника проверены живым MCP-чтением
с контролем ID, пространства и версии. Загрузка каталога в Agent Platform и включение
`partner_answer` только для тестовой формы `2430464` остаются отдельными действиями перед
сквозной приёмкой реальной модели и тестовой подзадачи Pyrus.
