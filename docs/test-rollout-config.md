# Конфигурация rollout MVP

MVP принимает входящие события только из формы чатов Pyrus `1165239`. Форма `1096731`
служит только целью для создаваемых подзадач и не должна включаться во входящий whitelist.

## Безопасное состояние до приёмки

В документе БД Agent Platform `config` оставьте форму в режиме `handover_only`:

```json
{
  "forms": {
    "1165239": {
      "role": "chat",
      "environment": "production",
      "knowledgeExecution": "handover_only"
    }
  },
  "subtaskFormId": 1096731
}
```

В этом режиме агент может распознать тему, собрать сведения, поставить достоверные поля и
подготовить материал оператору, но не отправляет партнёру найденную инструкцию. Отсутствующее
или неизвестное значение `knowledgeExecution` также трактуется как `handover_only`.

## Включение подготовленных ответов

После сквозной приёмки замените только режим формы:

```json
{
  "forms": {
    "1165239": {
      "role": "chat",
      "environment": "production",
      "knowledgeExecution": "partner_answer"
    }
  },
  "subtaskFormId": 1096731,
  "subtaskClaimTtlMs": 120000
}
```

Поле связи в форме не настраивается: подзадача получает `parent_task_id`, а поле `95`
остаётся за существующей интеграцией КЦ. `subtaskClaimTtlMs` можно не указывать — 120 секунд
уже заданы в коде. Уменьшать окно без живой проверки задержек Pyrus не следует.

`knowledgeExecution` является разрешением всей формы, поэтому менять его следует только в
согласованное окно приёмки или после проверки на изолированной копии формы. Само значение
не расширяет каталог: партнёрский ответ всё равно возможен только для подготовленной темы,
разрешённого рынка и одобренных источников.

В документ БД `knowledge_catalog` загружается содержимое
`docs/knowledge_catalog.json` из того же коммита, который деплоится на платформу. До
включения рейтингов их статья должна быть опубликована, а её четыре разрешённых источника —
повторно проверены живым MCP-прогоном.
