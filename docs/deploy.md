# Деплой и файлы, которые стирает платформа

Деплой делает сама платформа: она забирает `main` из GitHub, а после деплоя пишет туда
обратно свой экспорт. То есть `git push` — это и есть деплой, а `main` — общая ветка,
в которую пишут двое: мы и платформа.

## Что стирает экспорт

**Экспорт владеет всем корнем репозитория.** Он оставляет только то, что считает ресурсами
проекта, и удаляет остальное:

| Остаётся | Удаляется |
|---|---|
| `manifest.yml`, `settings.yml` | `docs/` |
| `nodes/`, `functions/` | `tests/` |
| `integrations/`, `credentials/` | `tools/` |
| `.agent/`, `CLAUDE.md` — но он их **перезаписывает** | всё остальное новое |

Проверено: в ветке после деплоя `docs/` и `tests/` отсутствуют целиком. Раньше в
`project-map.md` было написано обратное — что они в безопасности, потому что ресурсами
читаются только шесть путей. Это неверно, и на этом уже один раз потерялись файлы
(`6df6754 merge: keep tests and docs the Pyrus export does not know about`).

`.agent/` и `CLAUDE.md` экспорт перезаписывает своими версиями. **Ничего своего туда не
кладите** — оно проживёт до первого деплоя. Именно поэтому `docs/` лежит в `docs/`.

## Правило

> Всё, что не является ресурсом проекта, живёт в `docs/`, `tests/` или `tools/`.
> Эти три каталога — **защищённые**: каждый деплой их удаляет, и каждый раз они
> восстанавливаются со нашей стороны при слиянии.

Новый каталог вне этого списка не выживет. Нужен ещё один — добавьте его в `$PROTECTED`
в `tools/deploy.ps1` и в таблицу выше, одной правкой в обоих местах.

## Как деплоить

```powershell
pwsh tools/deploy.ps1
```

Скрипт делает то, что иначе делается руками и однажды будет забыто:

1. отказывается работать, если в рабочем дереве есть несохранённые правки;
2. `git fetch`, и если платформа что-то прислала — сливает;
3. восстанавливает `docs/`, `tests/`, `tools/` со своей стороны;
4. **проверяет, что ни один файл из защищённых каталогов не исчез** — и прекращает работу,
   если исчез, вместо того чтобы отправить потерю в GitHub;
5. прогоняет `node tests/run.js` и не пушит при падении;
6. коммитит слияние и пушит, то есть запускает деплой.

Шаг 4 — то, ради чего скрипт написан. Шаг 5 — бесплатное следствие: сломанное не уедет
в прод.

## Если делаете руками

```powershell
git fetch origin
git merge --no-commit origin/main          # будут конфликты modify/delete по docs/ и tests/
git checkout HEAD -- docs tests tools      # восстановить со своей стороны
git add docs tests tools
git diff --cached --diff-filter=D --name-only HEAD -- docs tests tools   # ДОЛЖНО быть пусто
node tests/run.js
git commit
git push origin main
```

Конфликты вида `CONFLICT (modify/delete): … deleted in origin/main and modified in HEAD` —
это норма для этих каталогов, а не признак проблемы. Разрешаются всегда в одну сторону:
берём свою версию.

## Что ещё присылает экспорт

Безобидное, принимать как есть:

- координаты узлов на канве (`position: x/y`) — платформа их переставляет при раскладке;
- переносы строк в длинных значениях `schema.yml` — экспортёр переоформляет их в свой стиль
  с экранированными продолжениями, текст при этом не меняется;
- `.agent/rules/*` — генерируется платформой.

## Перед выходом в прод

- `subtaskFormId` в `createSubtask/code.js` (`const DEFAULTS`) — сейчас **тестовая** `2454249`,
  вернуть `1096731`;
- `config.forms` — заменить тестовые id форм чатов и тикетов на продовые;
- `config.forms.<тикеты>.requireApprover: true` — на проде признак «бот на первом этапе»
  работает и его стоит включить;
- `origin-key` в `integrations/` и `credentials/` не трогать: платформа подставляет их сама.
