# Как разметить статью для бота техподдержки

Эта статья — справочник для редакторов Базы Знаний. Она объясняет, как оформить статью так,
чтобы ею мог пользоваться бот техподдержки. Статью без разметки бот просто не видит: обычные
статьи пространства ему не мешают и в его каталог не попадают.

> Примеры ниже нарочно оформлены **без** подсветки синтаксиса. Иначе эта статья сама была бы
> размечена как сценарий бота: признак разметки — блок JSON, и справочник, показывающий такой
> блок с подсветкой, оказался бы неотличим от настоящего сценария.

## Что нужно добавить в статью

Блок JSON с полем `schema`. Всё остальное — по обстоятельствам.

```
{
  "schema": "agent-topic/1",
  "key": "pos_shift_24h",
  "description": "смена превысила 24 часа, не закрывается смена, не выходит Z-отчёт",
  "phrasings": ["смена превысила 24 часа", "не закрывается смена"],
  "route": "solver",
  "onFail": "escalate"
}
```

| Поле | Обязательно | Что это |
|---|---|---|
| `schema` | да | Всегда `agent-topic/1`. По нему статья и опознаётся как сценарий |
| `key` | да | Идентификатор статьи: латиница, цифры, `_`. По нему статью видно в логах |
| `description` | да | Когда сценарий подходит. Этим текстом бот выбирает статью |
| `phrasings` | да | Как об этом просят партнёры, их словами |
| `route` | нет | `solver` (по умолчанию) — решаем по статье; `subtask` — сразу подзадача; `escalate` — сразу человеку |
| `onFail` | нет | Что делать, если решение не помогло: `escalate` или `subtask` |

## Текст статьи и есть текст решения

Если в блоке нет полей `article`, `steps` или `nodes`, решением становится **само тело
статьи** — всё, что написано ниже блока. Отдельно дублировать текст в блок не нужно и
вредно: две копии одного знания разъедутся на первой же правке.

То есть чтобы отдать боту готовую инструкцию, достаточно добавить к ней блок из пяти полей.

## Когда одного текста мало

- **Несколько решений по очереди** («проверьте крышку», не помогло — «проверьте ленту»):
  список `steps`. Бот выдаёт по одному за раз, иначе после «не помогло» предлагать нечего.
- **Нужны заполненные поля для подзадачи или разный исход в разных случаях**: дерево `nodes`.
  Только оно гарантирует, что данные собраны, а исход выбран по ветке.

Оба уровня описаны в репозитории бота (`docs/knowledge-tree-format.md`), и правило выбора
одно: **самый простой уровень, который даёт нужный результат.** Дерево — не признак
качества, а инструмент под задачу, и поддерживать его дороже всего.

## Черновик боту не виден

В каталог бота попадают только **опубликованные** статьи. Пока статья в черновиках, её можно
спокойно дописывать: партнёрам она не отвечает.

## Что важно знать про `description`

Этим текстом статья соревнуется с другими за обращение партнёра, поэтому:

- пишите **признаки проблемы**, а не общие слова: «пиццерия», «Додо», «точка» есть в любом
  обращении и притягивают чужие вопросы;
- границы («не относится к…») полезны: их читает модель, которая выбирает статью;
- `key` в выборе не участвует вовсе — называйте его как удобно читать в логе.

## Если что-то оформлено неправильно

Синхронизация с ботом называет каждую ошибку по имени статьи: нечитаемый блок, отсутствие
`description` или `phrasings`, два уровня решения одновременно, ветка дерева в никуда. Пока
ошибка не исправлена, **ни одна** статья в каталог не уезжает — иначе половина обновления
попала бы к партнёрам как готовое знание.
