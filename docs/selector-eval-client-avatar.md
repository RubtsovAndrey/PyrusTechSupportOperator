## Действия пользователя

1. В dev-проекте нажать **Pull**.
2. В **Базы данных → Pyrus Bot Database** открыть существующую запись
   `selector_eval_cases`. Заменить её значение всем JSON из
   `/tmp/pyrus-selector-eval-cases-v2.json`, без дополнительной обёртки key/value.
   В файле шесть случаев: четыре прежних сохранены без изменений, два добавлены.
   Сохранённые отчёты находятся в других записях и этим действием не меняются.
3. Открыть тестирование **Dev - check setup** или **Dev - Selector evaluation**.
   Отправить `client-avatar-full`, дождаться **Collect sample 5**, выгрузить лог.
4. Отправить `client-avatar-noise`, также дождаться завершения и выгрузить лог.

Всего десять реальных вызовов Terra. Публикация и Pyrus для этой проверки не нужны.
Прежние четыре команды повторять не требуется.

## Воспроизведение файла

JSON содержит исходные материалы БЗ и хранится вне Git. `/tmp` может очищаться;
файл теперь можно восстановить непосредственно из сохранённых трасс:

```sh
node tools/build-selector-eval-cases.js \
  /Users/andreyrubtsov/Documents/pyrus_tasks_for_tracing/050926_astra_avatar_city_terra_fix/all-logs-1788614866974.json \
  /Users/andreyrubtsov/Documents/pyrus_tasks_for_tracing/050926_astra_avatar_city_terra_long_avatar_fail/all-logs-1788615583439.json \
  /tmp/pyrus-selector-eval-cases-v2.json \
  /Users/andreyrubtsov/Documents/pyrus_tasks_for_tracing/050926_astra_avatar_city2/all-logs-1788609159865.json
```

Из трассы извлекается единственный различимый вход `operatorEvidenceRequest`;
при отсутствии или неоднозначности сборка останавливается. Значения реальных
taskId/commentId в набор не переносятся. Хеши четырёх прежних случаев сверены
с уже принятыми живыми отчётами: совпадают.
