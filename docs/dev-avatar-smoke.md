# Следующий этап: сквозная подсказка оператору в dev

После шести серий Selector (30/30 ожидаемых результатов) нужно проверить поиск свежих
статей, отбор, Composer и доставку внутренней сводки в одном чате. Код модели сейчас
менять не требуется. Стенд не подтверждает качество всего этого пути.

## Сначала определить подключение

По полученным трассам подтверждены только Test-канал dev и доступы к БД/БЗ/моделям.
Публикация dev и переключение тестовой формы Pyrus ещё не подтверждены.

Если тестовая форма `2430464` всё ещё направлена в прежний проект main:

1. В `PyrusTechSupportOperator-dev` получить актуальную ветку dev и опубликовать проект.
2. Сохранить прежний адрес webhook для возврата. В настройках интеграции **тестовой**
   формы заменить его на адрес dev:
   `https://agentplatform.just-ai.com/workflow-trigger/e78aebc0-9b6e-42ab-aab1-eaba33ac1a2a`.
3. Проверить, что прежний проект больше не получает обращения этой формы; две среды
   не должны одновременно отвечать на один чат. Не переключать реальные формы.

Если тестовая форма уже подключена к dev, повторно менять адрес не нужно. В первой
трассе полного чата проверить project-key `pyrustechsupportoper-1000299722-YwT` и
вход `trigger_webhook_pyrus`.

## Один новый чат

Использовать тестовую форму Pyrus, не виджет команд Selector. Не продолжать старую
задачу, состояние которой осталось в БД main.

1. Начать вопросом: `Как поменять аватарку у курьера?`
2. На запрос юнита ответить: `Москва 0-22`.
3. Если бот уточнит бизнес, ответить: `Пиццерия`.
4. Дождаться передачи оператору и внутренней сводки. Выгрузить логи всех витков
   из dev-проекта в отдельную папку.

Критерии: вопрос сохранён после уточнений, поиск читает актуальную БЗ, выбран источник
о сотруднике, в сводке есть полезная цитата и обоснованный черновик. Нет подмены
сотрудника клиентом, советов по ClientUUId/Kibana и обещания изменения аватара в
интерфейсах, которых источник не описывает. Неподготовленная тема передаётся человеку;
черновик предназначен оператору.

Если во время уточнений поведение отличается, сохранить фактическую трассу: не
подгонять разговор под ожидания. Для анализа уже есть сценарий
`unknown-courier-avatar-business-later` в `tests/live/scenarios.json` и инструмент
`tools/read-trace.js`.
