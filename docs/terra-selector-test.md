## Что произошло в первом smoke

Чат `377340756`, папка `050926_astra_avatar_city_terra_first_test`, runtime `2031bf2`.
Платформа передала Terra `tools: [switchToState]`, несмотря на `tools: []` в agent YAML.
Провайдер ответил HTTP 400, адаптер обернул его в 502:

> Function tools with reasoning_effort are not supported for gpt-5.6-terra in /v1/chat/completions.

В сообщении предложены Responses API или `reasoning_effort: none`. Текущая схема agent-узла
не предоставляет эти настройки. Для Selector инструменты вообще не требуются, поэтому
узел заменён на обычную функцию с `Llm.sendRequest`. Деловые инструкции сохранены;
скрытая оболочка agent-узла больше не участвует. Это отдельное изменение транспорта,
его нужно учитывать при последующем сравнении моделей.

Поиск прочитал шесть кандидатов, но отбора и черновика не было. Parser вернул `invalid`,
Composer был пропущен, чат передан оператору без предметного ответа партнёру. Результат
сценария 32/42. Это отказ подключения, не оценка качества Terra. `read-trace` теперь
показывает вложенную причину провайдера вместо `unknown error`.

## История подготовки повторного живого прогона

**Перед следующим Pull:** восстановление `263546d` не изменило блок в интерфейсе.
В YAML функции обнаружен и исправлен неверный формат параметров: вместо скаляров нужны
дескрипторы `type/value/filled-ai`, как требует `.agent/rules/node-types.md`.
`llmModel` имеет тип `LLM_MODEL`, лимит — `INTEGER` со строковым `value: "8192"`.
1365 локальных проверок проходят, включая отклонение прежнего формата и передачу
аргументов из реального графа. Это возможная причина отказа импорта, пока без подтверждения
серверными логами. До удаления узлов в два этапа повторить Pull с исправленным YAML.

**Повтор от 5 сентября, задача `377343334`: исправленный узел не выполнялся.**
В папке `050926_astra_avatar_city_terra_second_test` лежат две отдельные задачи: копия
первого лога `all-logs-1788610743420.json` и новый `all-logs-1788612385019.json`.
Новый файл нужно разбирать отдельно, иначе два чата ошибочно считаются двумя витками.

В новой трассе в 15:31 МСК зафиксированы `blockType: system.agent`,
`blockState: /agent_operator_evidence_selector` и `tools: [switchToState]`.
Вызова `Llm.sendRequest` и маркера `selectOperatorEvidence: requesting` нет.
Хотя `ccc49a8` уже находился в GitHub, активный runtime использовал прежний узел.
Пользователь затем подтвердил старый блок «Агент» при статусе последней опубликованной
версии. Экспорт платформы `b6fa0be` (16:00 МСК) удалил функцию и вернул agent-узел в Git.
Это подтверждает расхождение состояния платформы и отправленного исправления.
По этой трассе нельзя признать неработоспособным новый явный вызов.

Пользователь нашёл [описание пользовательских параметров LLM в Just AI](https://docs.agentplatform.just-ai.com/blog/2026/06/24/release/):
настройка `reasoning_effort` доступна в «Прямой доступ → Своя LLM». Текущая интеграция
имеет `is-direct-access: false`, поэтому добавление неизвестного параметра в agent YAML
не является подтверждённым решением. Это ограничение настройки, а не доказательство,
что модель с reasoning не может работать без function tools.

После восстановления исправления в Git до следующего чата выбрать **Pull** в меню Git
платформы. Проверить блок «Функция» с `ID_Tools.selectOperatorEvidence` /
`func_select_operator_evidence`, затем **Опубликовать**. При конфликте нужна восстановленная
версия из репозитория; выбор версии целиком описан в
[документации Just AI](https://docs.agentplatform.just-ai.com/flow-builder/git/).
Одинаковое название «Operator Evidence Selector» у агента и функции недостаточно.
Подключённого браузера в сессии Codex нет; требуется проверка интерфейса пользователем.

После обновления тестового проекта открыть **новую** задачу формы `2430464` и написать:

> Тамбов-1, нужно поменять аватарку у курьера

Выгрузить трассу в отдельную папку. Разбор:

```bash
node tools/read-trace.js /path/to/new/log.json --scenario unknown-courier-avatar-terra-direct --out /tmp/terra-selector-report.txt
```

Кроме продуктовых критериев проверить сырой LLM-запрос внутри Operator Evidence Selector:
модель Terra, отсутствие ошибки транспорта/параметров и обрезанного JSON, успешный переход
через `parseOperatorEvidence`. Остальные LLM-запросы должны остаться GPT-4.1-mini.
Handover сам по себе не доказывает работу Terra: при ошибке узла он тоже сохраняется.
Новый сценарий дополнительно проверяет настоящий id узла и маркеры явного вызова.
У старого повторного runtime — 32/47, включая отсутствие нового узла; локально 1362 проверки.

Далее — повтор с неоднозначным юнитом: «Как поменять аватарку у курьера?» → «Москва 0-22»
→ «Пиццерия», сценарий `unknown-courier-avatar-business-later`.

## Сравнение и откат

Этот живой smoke не заменяет сравнение на одинаковых входах: поисковая выдача может
измениться. Замороженные входы и план отдельного сравнения Selector/Composer описаны в
[`avatar-evidence-live-review-2026-09-05.md`](avatar-evidence-live-review-2026-09-05.md).
Первый профиль отличается моделью и бюджетом генерации; при сравнении фиксировать оба.
Новый способ вызова подтверждён трассой `377354226`; устойчивость качества и результат
на прежнем сложном входе ещё не проверены. 1365 локальных проверок проходят, включая отсутствие инструментов в явном запросе,
изоляцию контекста, ответ с неожиданным tool call и передачу при ошибке транспорта.

Для сравнения с baseline в `nodes/functions/func_select_operator_evidence.yml` задать
`parameters.parameters.llmModel.value: 1000299722-open_ai_gpt41mini-tme` и согласованный
бюджет `maxCompletionTokens.value` (строка в дескрипторе `INTEGER`)
(у старого baseline — 2000). Явный вызов оставить одинаковым для обеих моделей. Затем выполнить
проверки, коммит и `tools/deploy.ps1`. Менять остальные узлы для отката не требуется.
