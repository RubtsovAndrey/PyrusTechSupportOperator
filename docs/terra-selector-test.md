# Тестовая конфигурация Terra в Selector

Подготовлена 5 сентября 2026 года по запросу Андрея. Первый agent-вызов был отклонён провайдером. В `aa85343` Selector переведён на
явный `Llm.sendRequest` с `tools: []`; новый способ вызова ещё требует живого smoke.

| Параметр | Значение |
|---|---|
| Изменённый узел | `func_select_operator_evidence` |
| Интеграция | `1000299722-open_ai_gpt56terra-swl` |
| Модель провайдера | `just-ai/openai-proxy/gpt-5.6-terra` |
| Лимит генерации | 8192 вместо 2000 |
| Остальные роли, включая Composer | GPT-4.1-mini |
| Предметные инструкции, вход, чтение БЗ, parser и handover | прежние |
| Способ вызова | функция `ID_Tools.selectOperatorEvidence`, затем переход графа |

Лимит увеличен как стартовый резерв для reasoning и JSON с цитатами. Это инженерная
настройка эксперимента, а не найденный оптимум. Лимит видимого результата parser прежний:
до трёх цитат по 30–900 символов. Параметр reasoning effort не добавлен: в текущей схеме
Agent Platform его нет, ранее неизвестные поля исчезали при экспорте.
В явный вызов передаются только интеграция, messages с полем text, tools: [] и лимит.
Temperature, topP, история и служебный switchToState кодом не передаются. Фактический
HTTP-запрос нового способа и расход токенов ещё нужно проверить живой трассой.
Справка по модели: [GPT-5.6 Terra](https://developers.openai.com/api/docs/models/gpt-5.6-terra).

## Что произошло в первом smoke

Чат `377340756`, папка `050926_astra_avatar_city_terra_first_test`, runtime `2031bf2`.
Платформа передала Terra `tools: [switchToState]`, несмотря на `tools: []` в agent YAML.
Провайдер ответил HTTP 400, адаптер обернул его в 502:

> Function tools with reasoning_effort are not supported for gpt-5.6-terra in /v1/chat/completions.

В сообщении предложены Responses API или `reasoning_effort: none`. Текущая схема agent-узла
не предоставляет эти настройки. Для Selector инструменты вообще не требуются, поэтому
узел заменён на обычную функцию с `Llm.sendRequest`. Деловые инструкции сохранены;
скрытая оболочка agent-узла больше не участвует. Это отдельное изменение транспорта,
его нужно учитывать при последующем сравнении моделей.

Поиск прочитал шесть кандидатов, но отбора и черновика не было. Parser вернул `invalid`,
Composer был пропущен, чат передан оператору без предметного ответа партнёру. Результат
сценария 32/42. Это отказ подключения, не оценка качества Terra. `read-trace` теперь
показывает вложенную причину провайдера вместо `unknown error`.

## Повтор живого прогона

После обновления тестового проекта открыть **новую** задачу формы `2430464` и написать:

> Тамбов-1, нужно поменять аватарку у курьера

Выгрузить трассу в отдельную папку. Разбор:

```bash
node tools/read-trace.js /path/to/new/logs --scenario unknown-courier-avatar --out /tmp/terra-selector-report.txt
```

Кроме продуктовых критериев проверить сырой LLM-запрос внутри Operator Evidence Selector:
модель Terra, отсутствие ошибки транспорта/параметров и обрезанного JSON, успешный переход
через `parseOperatorEvidence`. Остальные LLM-запросы должны остаться GPT-4.1-mini.
Handover сам по себе не доказывает работу Terra: при ошибке узла он тоже сохраняется.

Далее — повтор с неоднозначным юнитом: «Как поменять аватарку у курьера?» → «Москва 0-22»
→ «Пиццерия», сценарий `unknown-courier-avatar-business-later`.

## Сравнение и откат

Этот живой smoke не заменяет сравнение на одинаковых входах: поисковая выдача может
измениться. Замороженные входы и план отдельного сравнения Selector/Composer описаны в
[`avatar-evidence-live-review-2026-09-05.md`](avatar-evidence-live-review-2026-09-05.md).
Первый профиль отличается моделью и бюджетом генерации; при сравнении фиксировать оба.
Результат нового способа вызова до повторной живой трассы считается непроверенным.
1359 локальных проверок проходят, включая отсутствие инструментов в явном запросе,
изоляцию контекста, ответ с неожиданным tool call и передачу при ошибке транспорта.

Для сравнения с baseline в `nodes/functions/func_select_operator_evidence.yml` задать
`llmModel: 1000299722-open_ai_gpt41mini-tme` и согласованный бюджет maxCompletionTokens
(у старого baseline — 2000). Явный вызов оставить одинаковым для обеих моделей. Затем выполнить
проверки, коммит и `tools/deploy.ps1`. Менять остальные узлы для отката не требуется.
